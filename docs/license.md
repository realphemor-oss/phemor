# 激活码（授权）· 运营手册

目标：**初中包免费，其余四个包（高中、大学、雅思进阶、旅游）必须有你签发的激活码才能装进「非莫」**。
即使客户 A 把网页源码、`.phemor` 文件都转给了客户 B，B 没有你给的激活码，也只能用初中包。

## 1. 原理（三句话）

1. 高中/大学/雅思进阶/旅游四个包的内容文件用 AES-256-GCM 加密，加密后的文件放夸克网盘，谁都能下载，但没有密钥就是一堆乱码。
2. 激活码里装着这个客户能用的包的解密密钥，并用你的**私钥签名**；网页里只有**公钥**，只能验证、不能伪造。
3. 激活码可以**绑定设备**：客户先在自己的手机上复制「设备码」发给你，你签发的激活码只有那台手机能打开（设备私钥存在手机浏览器里，不可导出）。没绑定的是「通用码」，谁拿到都能用。

## 2. 你需要保管的东西（在你自己的电脑上）

`~/.phemor-license/`（可用环境变量 `PHEMOR_LICENSE_DIR` 改位置）：

| 文件 | 作用 | 丢了 / 泄露了 |
|---|---|---|
| `master.key` | 主密钥，决定所有包的加密密钥 | 丢了：没法再加密新包、没法给新客户出码（已装好的客户不受影响）。泄露：任何人都能自己造码，要整体换密钥 |
| `issuer-private.jwk` | 签名私钥，签发激活码 | 同上 |
| `issuer-public.jwk` | 公钥，可以公开 | 无所谓 |
| `issued.csv` | 签发记录（客户、包、设备、到期、完整激活码） | 方便查 |

**这个文件夹绝不能传 GitHub、夸克，也不要发给任何人。** 生成后马上复制一份到加密 U 盘 / 密码管理器附件。
这个文件夹在项目目录之外，所以不会被 `更新GitHub文件夹.sh` 带出去。

关于 YubiKey：它最适合保护 **GitHub 和 Cloudflare 账号**（用通行密钥/2FA，建议买两把，一把备用）。
想把签名私钥也放进 YubiKey（PIV）是可行的，但第一版没有这么做；备份好上面的文件夹，再给电脑开磁盘加密就够用了。

## 3. 一次性设置（只做一遍）

```bash
cd phemor
npm run license -- init
```

- 在 `~/.phemor-license/` 生成主密钥和签名密钥；
- 把**公钥**写进 `src/packs/issuer.ts`（这个文件要提交到 GitHub，是公开的，没问题）；
- 重新推送 GitHub，等网页部署完。网页没带公钥时，「授权」面板不会出现，加密包也装不了。

已有 `.git` 的旧目录不要直接推，照 `发布说明.md` 用 `更新GitHub文件夹.sh` 刷新干净的上传目录。

## 4. 生成要传夸克的包

```bash
npm run license -- release --in packs/lists --out "../上传夸克/非莫单词包"
```

- `1-初中包.phemor` 原样复制（明文，免费）；
- `2-高中包`、`3-大学包`、`4-雅思进阶包`、`5-旅游包` 加密后输出；
- 同样的输入得到同样的输出（固定时间戳，随机数只在激活码里），可以重复运行；
- 检查：`npm run packs:verify` 同款命令能核对加密包：`npx tsx scripts/pack/verify.ts "../上传夸克/非莫单词包/2-高中包.phemor"`。本机有主密钥时会完整解密核对，没有时只核对结构。

把输出文件夹里的文件传夸克（覆盖旧的明文版）。**务必确认夸克里没有留着旧的明文高中/大学/雅思/旅游包**，否则等于没加密。

套装配置在 `scripts/license/products.json`（哪个包免费、文件名、别名、密钥版本 `kv`）。

## 5. 给客户签发激活码

流程（每个客户一次）：

1. 客户在手机的「非莫」→ 单词包 →「授权」，点「复制设备码」，发给你（`PHD1.` 开头的一长串）。iPhone 要在**主屏幕上的 App** 里操作，因为它和 Safari 的数据是分开的。
2. 你在电脑上：
   ```bash
   npm run license -- issue --customer 张三 --packs all --device PHD1.粘贴客户的设备码 [--days 365]
   ```
   - `--packs`：`all`（四个付费包）或用逗号分隔，如 `高中,大学`；也认 `list-senior` 这样的包 id；
   - `--device`：不写就是**通用码**，不绑定设备（适合老师自己用，或客户不会分享时）；
   - `--days`：有效天数；不写是长期有效。
   - `--customer`：客户名，**默认只记在你自己的 `issued.csv` 里，不写进激活码**，客户手机上只显示「已激活」。想让名字显示在客户手机上（分享出去会暴露客户名，起威慑作用），再加 `--show-name`。
3. 把打印出来的 `PHEMOR1.…` 发给客户，客户粘贴到「授权」→「激活」，再选择夸克下载的包文件即可。

批量：做一个 `customers.csv`（表头 `customer,packs,device,days`，packs 留空=全部，device、days 可空），然后
```bash
npm run license -- batch customers.csv --out codes.csv
```
`codes.csv` 用 Excel 能直接打开（带 BOM）。绑定设备的客户需要每人先发来设备码，所以通常是通用码批量、绑定码单个签发。

查一个码：`npm run license -- show PHEMOR1.…`（验证签名，显示客户、包、设备、到期）。

## 5.1 规则细节

- **到期只影响新装和更新**：已经装进手机的内容永远能用，不会被收回。
- **一个设备码对应一台设备**。客户换手机要重新发设备码，你重新签发。同一台手机清除网站数据后设备码会变，也要重新签发。
- 客户重装（清除网站数据）后，已激活的码和已装的包都在浏览器里，会一起丢，需要重新激活、重新导入包。
- 一个客户可以有多个码（比如先买了高中包，后来加买大学包）；每个码独立。
- 客户名默认不写进激活码。加 `--show-name` 后，名字会显示在客户的「授权」面板里——分享出去的人等于把自己的名字交了出去，这是一个威慑。批量签发时用 `npm run license -- batch customers.csv --show-name`。

## 6. 诚实的局限

没有任何离线方案能做到绝对防拷贝：

- 技术很强的客户装好后，可以从自己手机的浏览器缓存里把已解密的图片和音频导出来。门槛很高，但不是不可能。
- 通用码一旦泄露就能被很多人用；绑定设备的码在别的设备上无效。要防分享，请用绑定码。
- **所有客户共用同一份加密文件**（这样夸克里只需放一份）。如果某个包的密钥被人公开，处理办法是把 `scripts/license/products.json` 里的 `kv` 加 1，重新 `release`，给仍然合法的客户重新签发激活码。旧版本的包和旧码就都失效了。
- 内容里 CC BY 4.0 授权的部分本来就是公开的（见 `CONTENT_LICENSE.md`），加密保护的是你整理好的整套词表、插画包和音频包的「打包形态」。

## 7. 测试

- 单元测试：`npm test`（含 `src/packs/crypto.test.ts`：加密往返、密钥派生、签名、篡改、过期、设备绑定）。
- 浏览器端到端：`python3 scripts/license/e2e_license.py`。用临时密钥构建网页，真实浏览器里验证：没码被拒绝且不写入缓存、坏码/篡改码/别人的绑定码被拒绝、通用码能装、绑定码只在那台设备有效。需要 `pip install playwright`，CHROME_PATH 指向 Chrome。

## 8. 技术细节（给以后的开发者）

- 加密包 manifest `format: 2`，多一个 `crypt: {alg: "A256GCM", kv}`；`pack.json` 保持明文，包里 `words.json` 和 `files/*` 全部加密。
- 文件加密：AES-256-GCM，密文 = iv(12) + 密文 + tag(16)，AAD = `phemor|<包id>|<站内路径>`（所以密文挪到别的路径/别的包会解密失败）。
- 包密钥 = HKDF-SHA256(master, salt `phemor-pack-v1`, info `pack:<id>:<kv>`)。
- 激活码 = `PHEMOR1.` + base64url(JSON{claims, sig})，签名是 ECDSA P-256 / SHA-256，对按键名排序的规范化 JSON 签名。
- 绑定码：ECDH P-256，用一次性密钥和设备公钥协商出共享密钥，再 HKDF（info `lid:<lid>`）得到 AES-GCM 密钥，包住各包的密钥。
- 浏览器和命令行用的是同一份 `src/packs/crypto.ts`（只依赖 Web Crypto）。
- 安装流程：先拿到密钥并试解密第一个文件（失败就整个不装，不写缓存），再逐个解密写入缓存。
